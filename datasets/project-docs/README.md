# Project documentation QA: authored D0 proposal

Status: **authored, unreviewed, no model trained**. Version: `t1-snapshot-d0-v1`.
These local sources describe the pinned T1 state of Hexweave on 2026-10-24. They
are historical evidence for this dataset, not claims about whatever code exists
when a model is later trained or queried. No external corpus or artifact was
downloaded. T1 train/valid data, held-out observations and runtime receipts were
not read to create the examples.

This is a supplied-evidence question-answering task. It does not provide broad
language pretraining, a retriever, a useful trained assistant, or a duration
estimate. The intended application is a narrow project-documentation assistant;
that interpretation remains subject to the user's eventual domain/usefulness
criterion. No operation described inside an excerpt is an instruction to the
dataset consumer or a request to run a command.

## Files and provenance

- `manifest.json`: schema/version, source and JSONL SHA256 values, rendering and
  byte bounds, counts, scope and outstanding review gates.
- `sources/`: nine complete, byte-identical local Markdown source snapshots.
- `source-pins.json`: the retained planning manifest used to pin those snapshots.
- `train.jsonl`: 60 handwritten examples: 52 answerable and 8 abstentions.
- `development.jsonl`: 12 handwritten examples: 10 answerable and 2 abstentions.
- `author_dataset.py`: deterministic rendering of the handwritten author list;
  it checks source pins, exact spans, duplicate questions and byte bounds while
  producing data. It is an authoring helper, not model code or a training command.

Source identity was taken from
`work/f-text-drive-t2/domain-data-measurements.json` in the orchestration workspace
and checked against its retained T1 stage. The source-pin manifest's SHA256 is
recorded, and its exact bytes are retained locally as `source-pins.json`.
Regeneration uses the local snapshots; the initial import alone used the retained
T1 stage. The snapshots preserve all bytes and original paths. Their existing
links are retained as source text; linked pages are not implicitly part of the
corpus. No final evaluation questions or answers have been authored.

Questions, concise answers and abstention decisions were manually authored by
`/root/review_contracts`, then rendered against exact source byte spans. They were
not extracted from a benchmark, generated by paraphrase expansion or approved by
an independent reviewer yet. Source faithfulness, semantic split separation and
answer completeness require the later independent data/evaluation review.

All questions and every excerpt/variant from a family remain in that partition.
In training, each question addresses a separate stated property: equations,
parameter credit, storage, counters, bounds, state lifetime or kernel behavior.
Development questions concern HTTP transport, benchmark schemas, request timing,
artifact binding and benchmark fixtures. Development deliberately excludes the
benchmark guide's F+Hex training discussion, which overlaps training facts.

Each row has a stable, manually assigned `fact_family_id`; these fine-grained IDs
identify targeted facts, not statistically independent observations. Several
different properties share a paragraph. Training has 41 unique evidence spans
and development has 9; repeated evidence is retained only for different questions
or a specifically unsupported query, not as purported new source information.
The 60/12 row counts do not measure independent linguistic evidence.

Before independent final-evaluation authorship, exclude facts already taught in
training/development, even when a reserved source phrases them differently. In
particular exclude shared generic routing/ternary facts, known text-versus-FP32
comparisons and generic no-quality/no-scaling conclusions. Reserved source files
may supply inference-time evidence later; they must never become training or
development inputs. The independent lane owns final cases, reference answers and
scoring keys. An untouched final test does not yet exist in this proposal.

Unsupported questions ask for a property absent from their supplied excerpt,
such as a numerical observation or parameter not stated there. `UNKNOWN` means
insufficient supplied evidence, not a claim that the information cannot exist
elsewhere. Models must not answer from unrelated training examples when evidence
does not support the requested fact.

## Exact model-visible format

Every JSONL row carries both exact rendered strings, plus source/answer metadata.
The input prompt is:

```text
Use evidence only; otherwise UNKNOWN.
SOURCE {source_id}:{start}-{end}
{evidence}
Q: {question}
A: 
```

There is no newline after the final `A: ` in the stored prompt. Offsets are
zero-based UTF-8 byte offsets in the complete source snapshot; `end` is exclusive.
The source reference in the prompt and completion addresses that exact excerpt.
Snapshot path and SHA256 are resolved through the manifest, not guessed from an
ID. Excerpts preserve original whitespace and qualifiers; no source text is
silently repaired or updated.

Completion is compact UTF-8 JSON with keys in the order `answer`, `citation`,
followed by exactly one newline. The answerable form is:

```json
{"answer":"<handwritten supported answer>","citation":"<source_id>:<start>-<end>"}
```

The exact abstention completion is `{"answer":"UNKNOWN","citation":null}\n`,
where `\n` denotes one actual trailing newline. Both fields and the newline are
part of the scored answer bytes. Evidence, question, prompt metadata and source
files are not additional supervised answer targets. Stop generation on newline
or the 192-byte output limit; reaching the limit without a valid completion is a
failure, not a silently repaired output.

The per-example limits are 80 envelope bytes, 144 question bytes, 608 evidence
bytes and 192 completion bytes, with prompt plus completion at most 1,024 byte
positions. `utf8_bytes` records the actual lengths. Do not load the raw JSONL
line as a training sequence: it duplicates evidence in metadata and prompt and
contains the reference answer. Train from `prompt` and `completion` only, using
answer-only target masking. JSONL metadata and future evaluation keys must not
leak into prompts. Any additional BOS/EOS symbol needs a charged position and a
newly declared serialization rule; the current format terminates with newline.

## Readback and remaining gates

Ordinary data generation/readback checked each source SHA256, every evidence byte
span, partition/source agreement, question uniqueness, and all rendered byte
bounds. Those mechanical checks are not independent review and are not a model
test. No test suite, build, training or final evaluation ran in this author lane.

Independent reviewers must check all handwritten answers and abstentions, preserve
scope qualifiers, and challenge semantic leakage. The integrator must validate
answer masking and exact prompt/completion loading, establish causal generation,
and obtain the separate numerical/resource/ownership gates before a bounded run.
Development is for debugging and model selection; it cannot be reported as sealed
assistant-quality evidence. Repeatedly training these small sources does not add
new independent language data or justify a forecast to broad assistant competence.
